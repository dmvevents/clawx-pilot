## Drive mechanism (and why)

The established Mac in-app lane (`scripts/app-usecase-recorded.ts`, osascript
System Events keystrokes) is TCC-blocked in this execution context:

```
execution error: System Events got an error: osascript is not allowed assistive access. (-25211)
```

(Reproduced twice, sandboxed and unsandboxed; window geometry reads worked but
synthetic click/keystroke are refused. Nothing reached the app on that lane.)

Fallback used: POST the prompt to the app's own host-API route
`/api/chat/send-with-media` (electron/api/routes/gateway.ts), which relays over
the app's established gateway connection via the SAME `chat.send` RPC the chat
composer submits through (src/stores/chat.ts `sendMessage`). The turn runs the
full in-app path — electron main -> gateway -> agent -> plugin tools — in the
app's own `agent:main:main` session, so the exchange renders in the app UI.
The per-boot host-API bearer token was recovered from the openclaw-gateway
child's env (`CLAWX_HOST_API_TOKEN`, threaded in by
electron/gateway/config-sync.ts) via sysctl `KERN_PROCARGS2` — the established
mechanism — held in memory only, never logged, stash deleted after the run.
