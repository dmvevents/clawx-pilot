# CLWX-67 — Reminder pipeline e2e: cron -> agentTurn -> visible chat prompt (Mac leg)

**Date:** 2026-09-05 · **Verdict: PASS** (all 11 harness assertions green, one confirmed live run)
**Harness:** `scripts/clwx67-reminder-e2e.ts` · **Artifacts:** `docs/evidence/clwx67-reminder/`

This is the first end-to-end proof of the agentTurn cron path on any platform. Before this run,
`~/.openclaw/cron/` did not exist on this machine — no cron job had ever fired.

## What the cron surface actually is

| Layer | Location |
|---|---|
| Create/list/update/delete/trigger routes | `electron/api/routes/cron.ts` (`POST/GET /api/cron/jobs`, `PUT/DELETE /api/cron/jobs/:id`, `/api/cron/toggle`, `/api/cron/trigger`) — thin relays to gateway RPCs `cron.add/list/update/remove/run` |
| Shipped job shape | `electron/main/moe-seed.ts` (`moe:seed-cron`): payload `{kind: 'agentTurn', message}`, `sessionTarget: 'isolated'`, `wakeMode: 'next-heartbeat'`, `delivery: {mode: 'none'}` — the harness creates the identical shape via the app's own POST route |
| Fire ground truth | `~/.openclaw/cron/runs/<jobId>.jsonl` (one `action:"finished"` entry per run with sessionId/sessionKey/summary/model/duration) |
| Turn ground truth | `~/.openclaw/agents/main/sessions/<sessionId>.trajectory.jsonl` (`model.completed`) |
| UI rendering | run executes in isolated session `agent:main:cron:<jobId>:run:<sessionId>`; the session appears in the sidebar as `Cron: <job name>` and renders as a normal chat transcript (fallback history via `GET /api/cron/session-history`) |
| Scheduling internals | bundled gateway `dist/schedule-*.js`: croner, schedule kinds `cron`/`every`/`at`, tz resolved from `schedule.tz` else `Intl.DateTimeFormat().resolvedOptions().timeZone` of the gateway process |

Constraint discovered: `sessionTarget: "main"` is only valid with `payload.kind: "systemEvent"`;
agentTurn jobs are isolated-session by design (bundled `dist/jobs-*.js` validation).

## Findings (defects observed live, beyond the acceptance)

1. **Cron timezone defect — reminders can fire at the wrong wall-clock time or never.**
   Neither shipped creation surface (`POST /api/cron/jobs`, `moe-seed.ts`) sets `schedule.tz`, so
   the gateway parses the expr in the timezone its process resolved at boot
   (`Intl.DateTimeFormat().resolvedOptions().timeZone`, cached by Node for process lifetime). On
   this machine the gateway resolved `Asia/Calcutta` (visible in the injected turn header:
   *"2:07 PM (Asia/Calcutta) / 08:37 UTC"*) while the system clock is Asia/Dubai. Run 1's
   local-wall-clock expr produced `nextRun` a full **year** out (2027-09-05) because the +5:30
   interpretation had already passed that day. Evidence in `run-summary.json`:
   `nextRunBeforeTzFix: 2027-09-05T03:07:00Z` vs `nextRunAfterTzFix: 2026-09-05T08:37:00Z` after
   pinning `{schedule: {kind:'cron', expr, tz:'UTC'}}` through the PUT route. Impact for the fleet:
   the seeded 3:30pm daily reminder fires at the gateway-process tz, not the principal's clock —
   wrong by hours if they diverge (laptop tz change without app restart, DST, imaging tz). Fix
   direction: creation surfaces should set `schedule.tz` to the current system IANA zone.
2. **Defer path re-schedules with a naive timestamp.** Honoring "3:40pm tomorrow", the agent's
   `cron` tool call wrote `at: "2026-09-06T15:40:00"` (no zone, reasoning "assuming the user's
   timezone is the same as the system's"); the gateway stored `2026-09-06T15:40:00.000Z` — 19:40
   local here, 4 h late. Same defect class as (1) on the write side of the `cron` agent tool.
3. **Defer re-scheduling works (positive finding).** The defer path is not a canned acknowledgment:
   the agent verified the date via `session_status`, created a real one-shot follow-up with
   `deleteAfterRun: true`, and confirmed in principal-appropriate language. The reminder loop is
   functionally closed.
4. **Trust cosmetics in the cron transcript** (principal-proxy lens, pre-existing classes):
   the user bubble leaks the raw `[cron:<uuid> <job name>]` prefix and the
   `Current time: … (Asia/Calcutta) / … UTC` header; the defer reply renders the model's `<think>`
   block verbatim (same leak class seen in the CLWX-65 screenshots). Also, the run log shows a
   harmless-but-noisy delivery resolution error (`"Channel is required (no configured channels
   detected)"`) even though `delivery.mode` fell back to none and `deliveryStatus` is
   `not-requested`.
