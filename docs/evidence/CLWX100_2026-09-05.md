# CLWX-100 — cron trust cosmetics: evidence (2026-09-05)

Card scope: four low-priority trust cosmetics observed during the CLWX-67 reminder
e2e and CLWX-65 evidence capture (principal-proxy lens). Disposition per item below.

## Item 1 — cron user bubble leaked `[cron:<uuid>]` + instructions + clock header: FIXED

**Fix:** `src/pages/Chat/message-utils.ts` — new `cleanCronRunText()` hooked into
`cleanUserText()` (which both `extractText` and `extractTextSegments` route user
text through). A user turn shaped `[cron:<job id> <job name>] <headline>\n\n
<instructions…>\nCurrent time: … (zone) / … UTC` now collapses to the headline
paragraph only. Fallbacks: single-paragraph job messages display in full; a turn
with no body displays the job name. Display-only — the payload sent to the model
is unchanged.

With the fix, the CLWX-67 evidence payload
(`docs/evidence/clwx67-reminder/ui-texts-after-open.txt`) renders as:

> Reminder: 3:45pm — submit today's Daily Report.

instead of the UUID + instruction block + `Current time: … (Asia/Calcutta) …` header.

## Item 2 — think-block leak in cron/defer replies: FIXED

**Fix:** `stripAssistantProviderWrappers()` now strips bounded `<think>…</think>` /
`[think]…[/think]` blocks anywhere in the reply (previously leading-only), and
truncates an unclosed mid-text think opener while keeping the text before it.
The existing `<final>`-recovery behaviour for fully-contaminated replies is
preserved (all 7 pre-existing tests still green).

## Item 3 — raw model id in composer: CLOSED, dev-only by code

The raw-id model dropdown is a diagnostic surface gated behind dev mode:
`src/pages/Chat/ChatInput.tsx:308-311` (`showModelPicker = modelOptions.length > 1
&& devModeUnlocked`) with the hard-rule comment at `ChatInput.tsx:260`.
`devModeUnlocked` defaults to `false` (`src/stores/settings.ts:101`) and is a
persisted opt-in. The principal-facing toggle (`src/components/chat/
ChannelToggle.tsx`) renders only "Online" / "On this device" by design.
The `gemini-2.5-flash` in the evidence screenshots came from the dev machine
with dev mode unlocked. No RC leak; no fix needed.

## Item 4 — spurious "Channel is required" in cron run journal: UPSTREAM, not fork-fixable in-tree

The exact string is thrown/recorded by the upstream gateway
(`node_modules/openclaw/dist/channel-selection-DARF15EW.js:122`): the run journal
records a speculative delivery resolution (`intended.channel: "last"`) even when
the job runs with `delivery.mode: none` and `deliveryStatus: not-requested`
(see `docs/evidence/clwx67-reminder/run-summary.json`). The fork already
suppresses it at every fork-owned surface: the cron:list auto-repair clears
`state.lastError` containing this string (`electron/main/ipc-handlers.ts:970`,
`electron/api/routes/cron.ts:532`) and the UI never renders the raw journal.
Patching the upstream dist mid-pilot was already rejected on CLWX-99; this item
is flagged for the next upstream merge pass instead.
